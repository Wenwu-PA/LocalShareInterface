# Ручная приёмка v0.1.0-rc1

Статус всех сценариев ниже: 🕐 ожидается результат пользователя.
Подготовленные команды Linux/служб не выдаются за выполненные здесь.
Используйте отдельные тестовые данные. Не запускайте два сервера с одной SQLite.
Обычный адрес Go — `https://localhost:8766/`, Python на 8765 к этой приёмке не относится.

## Что прислать по каждому сценарию

Номер раздела, PASS/FAIL, ОС и браузер, время, точный шаг и текст ошибки.
При FAIL приложите снимок экрана и последние 100 строк
`runtime/logs/lanbridge.log` (либо настроенного `storage.data/logs/lanbridge.log`).
Не присылайте `.env.go`, пароли, ключи TLS, cookie или URL с секретными токенами.
В командах журналов заменяйте путь только если меняли `storage.data`.

## 1. Чистая Windows 11 и запуск готового бинарника

1. На компьютере без Go/Node/Python создайте новую папку, скопируйте туда только
   `dist/lanbridge.exe`. Не переносите рабочую БД или `runtime`.
2. Откройте PowerShell в этой папке и выполните:

   ```powershell
   .\lanbridge.exe
   ```

3. Откройте `https://localhost:8766/`, создайте администратора, выйдите и войдите.
4. Остановите Ctrl+C, запустите той же командой. Войдите прежним паролем.

**Ожидается:** форма первого запуска только один раз, вход работает после перезапуска,
рантаймы не нужны; журнал содержит `server stopped cleanly` при Ctrl+C.
Самоподписанный сертификат по умолчанию вызывает предупреждение браузера.
Для проверки доверия используйте сертификат своего доверенного CA с SAN выбранного
имени/IP; передавайте клиенту только публичный сертификат CA, не ключ сервера.
**При ошибке:** общий пакет выше плюс вывод PowerShell и имя проверенного exe.

## 2. Телефон в LAN: QR, вход, загрузка и скачивание

1. На тестовом сервере скопируйте `go-config.example.yaml` в новый `config.go.yaml`.
   Задайте `server.host: 0.0.0.0`, порт 8766, отдельное хранилище.
   Запустите `dist\lanbridge.exe -config config.go.yaml`.
2. Узнайте IPv4 сервера командой `ipconfig`. Телефон и сервер подключите к одной
   доверенной Wi-Fi/LAN, без изоляции клиентов. В брандмауэре разрешите TCP 8766
   только для частного профиля и локальной подсети.
3. Откройте на ПК «Файлы» → «Подключить телефон». Укажите
   `https://<LAN-IP-сервера>:8766`, отсканируйте QR камерой телефона.
4. Проверьте сертификат для этого IP/имени, войдите. Загрузите фото с телефона;
   скачайте его на ПК и сравните размер/содержимое. Загрузите небольшой файл с ПК,
   скачайте на телефон и откройте.
5. Создайте временную ссылку на тестовый файл с паролем и лимитом 1, откройте QR
   в приватном окне телефона. Неверный пароль должен отказать, верный — скачать.
   Повторное скачивание должно быть запрещено. Отдельную новую ссылку отзовите
   на ПК и убедитесь, что она больше не выдаёт новый билет скачивания.

**Ожидается:** QR ведёт на LAN-IP, а не localhost; двусторонние файлы не повреждены;
гость видит только выбранный объект. Кнопки помещаются на экране телефона.
**При ошибке:** модель/ОС телефона, браузер, локальный адрес без токена, скриншот,
профиль брандмауэра; не присылайте QR секретной ссылки.

## 3. Дерево папок, ZIP и большой файл с обрывом

1. Создайте на ПК тестовую папку `rc-tree`, вложенные `a/b`, `empty` и два текстовых
   файла (один в корне, другой в `a/b`). Перетащите папку из проводника в «Файлы»
   в браузере, поддерживающем перетаскивание каталогов.
2. Откройте дерево на сервере: все каталоги, включая `empty`, должны сохраниться.
   Скачайте корневую папку как ZIP и распакуйте в новый каталог. Сравните имена,
   вложенность, пустые каталоги и содержимое файлов.
   Диалог «Загрузить папку» может не передавать пустые каталоги из-за браузерного API;
   для данного шага используйте перетаскивание.
3. Выберите несекретный файл больше 5 ГиБ при достаточном свободном месте на обоих
   устройствах. Запишите SHA-256 до загрузки:

   ```powershell
   Get-FileHash -Algorithm SHA256 -LiteralPath 'D:\test\large.bin'
   ```

4. Начните загрузку с другого компьютера. После передачи части файла отключите
   Wi-Fi/кабель именно клиента, затем восстановите связь и возобновите передачу
   того же файла через интерфейс. Не удаляйте ожидающую загрузку.
5. Скачайте готовый файл в другой каталог, повторите `Get-FileHash` для него.

**Ожидается:** структура ZIP сохранена; докачка идёт с подтверждённой позиции;
хеши большого файла совпадают; неполный файл не опубликован как завершённый.
Рост памяти проверяется отдельно суточным сценарием, не по одному снимку диспетчера задач.
**При ошибке:** хеши, размеры, браузер, момент обрыва, статусы истории передач,
журнал сервера. Сам большой файл присылать не нужно.

## 4. Реальные LAN/WAN, инциденты и уведомления

1. Добавьте LAN TCP-проверку доступного порта другого устройства и WAN HTTP-проверку
   доступного вам внешнего адреса; интервал 20 с, порог 2 ошибки.
2. Дождитесь статуса «Работает». Остановите тестовую службу на другом устройстве:
   должен открыться инцидент после порога ошибок. Восстановите службу — инцидент закрывается.
3. Настройте свой канал Telegram/SMTP/Webhook по [go-notifications.md](go-notifications.md).
   Отправьте тестовую тревогу только своему получателю, убедитесь в доставке.
4. Находясь рядом с сервером (не через единственное удалённое соединение), отключите
   WAN на маршрутизаторе, оставив LAN. Дождитесь сбоя WAN-монитора, проверьте очередь.
5. Восстановите WAN и дождитесь доставки накопленного сообщения. Повторная попытка
   может быть отложена до часа после серии неудач.

**Ожидается:** LAN-интерфейс доступен без WAN, инцидент виден, сообщение сохраняется
в очереди и доставляется после восстановления. Повторы допустимы при доставке
«как минимум один раз»; потеря сообщения — FAIL.
**При ошибке:** время отключения/возврата, ID инцидента/доставки, тип канала,
текст ошибки без токена или почтового пароля.

## 5. Cloudflare и доступ с мобильного интернета

1. Установите cloudflared из официального источника, задайте путь в
   `external.cloudflared`, следуйте [go-external.md](go-external.md).
2. После запуска сервера убедитесь, что внешний доступ выключен.
3. Создайте ссылку только на тестовый файл. Включите Cloudflare с подтверждением;
   подставьте полученный внешний origin в гостевой адрес через интерфейс.
4. Отключите Wi-Fi телефона. Откройте ссылку через мобильный интернет, скачайте файл.
   На том же публичном origin откройте `/api/me` и `/api/files` — доступ должен быть закрыт.
5. Нажмите «Отключить сейчас»: новые подключения по внешней ссылке должны перестать
   работать. Перезапустите LANBridge: внешний доступ должен остаться выключенным.

**Ожидается:** работает только гостевой файл; административный API недоступен;
публикация не восстанавливается сама. Наличие/отсутствие публичного IP само по себе
не определяет результат исходящего туннеля.
**При ошибке:** этап, состояние туннеля, HTTP-код, текст ошибки провайдера без секретов,
тип сети телефона. Не присылайте полный гостевой URL.

## 6. Внешний heartbeat

1. На независимом внешнем наблюдателе создайте проверку пропавшего сигнала и настройте
   тревогу своему получателю после 90 с без сигнала.
2. В «Уведомлениях» настройте URL наблюдателя по
   [go-notifications.md](go-notifications.md). Дождитесь успешного сигнала на обеих сторонах.
3. Отключите WAN сервера, сохранив интернет у получателя, либо штатно остановите сервер.
4. Убедитесь, что тревогу прислал именно внешний наблюдатель. Восстановите соединение
   или сервер и дождитесь восстановления статуса у наблюдателя.

**Ожидается:** внешний сервис замечает отсутствие сигнала независимо от локальной
очереди; успешный GET в LANBridge без внешней тревоги не закрывает проверку.
**При ошибке:** интервалы, время последнего сигнала, настройки порога без секретного URL,
журнал событий наблюдателя и результат доставки.

## 7. Windows Service Control Manager

Выполняется пользователем в PowerShell администратора, на отдельной тестовой установке.
Подробности прав и удаления: [go-deployment.md](go-deployment.md).

1. Создайте `C:\Program Files\LANBridgeRC` для exe и
   `C:\ProgramData\LANBridgeRC` для новой конфигурации и данных.
   Скопируйте собранный exe и пример конфига. В конфиге укажите абсолютные пути
   `storage.data: C:/ProgramData/LANBridgeRC/runtime` и
   `storage.root: C:/ProgramData/LANBridgeRC/files`.
2. Создайте эти два каталога. Дайте LocalService (SID `S-1-5-19`) права изменения
   только на runtime/files и чтения config/exe. Обычные пользователи не должны
   менять exe или config. Например, для подготовленных каталогов:

   ```powershell
   icacls 'C:\ProgramData\LANBridgeRC\runtime' /grant '*S-1-5-19:(OI)(CI)M'
   icacls 'C:\ProgramData\LANBridgeRC\files' /grant '*S-1-5-19:(OI)(CI)M'
   icacls 'C:\ProgramData\LANBridgeRC\config.go.yaml' /grant '*S-1-5-19:R'
   icacls 'C:\Program Files\LANBridgeRC\lanbridge.exe' /grant '*S-1-5-19:RX'
   ```

3. Если `LANBridgeGo` уже зарегистрирована, сначала сохраните её конфигурацию и
   используйте согласованный тестовый компьютер; не заменяйте действующую службу.
   Из корня проекта:

   ```powershell
   .\scripts\install-go-service.ps1 -Binary 'C:\Program Files\LANBridgeRC\lanbridge.exe' -Config 'C:\ProgramData\LANBridgeRC\config.go.yaml'
   Start-Service LANBridgeGo
   Get-Service LANBridgeGo
   ```

4. Откройте localhost:8766, создайте администратора и загрузите тестовый файл.
   Выполните `Restart-Service LANBridgeGo`, проверьте вход и файл.
   Выполните `Stop-Service LANBridgeGo`, проверьте закрытие порта и чистый журнал.

**Ожидается:** Running/Stopped, данные сохраняются, остановка завершается без таймаута.
**При ошибке:** `Get-Service LANBridgeGo`, `sc.exe qc LANBridgeGo`, журнал приложения
и событие SCM из журнала Windows; пути допустимы, секреты исключите.

## 8. Linux systemd

На отдельной Linux amd64 с systemd, из копии проекта с кросс-собранным бинарником.
Если пользователь/каталоги уже существуют, проверьте их назначение до копирования.

```sh
sudo useradd --system --home /var/lib/lanbridge --shell /usr/sbin/nologin lanbridge
sudo install -d -o root -g root /opt/lanbridge /etc/lanbridge
sudo install -d -o lanbridge -g lanbridge /var/lib/lanbridge /srv/lanbridge
sudo install -m 755 dist/lanbridge-linux-amd64 /opt/lanbridge/lanbridge
sudo install -m 644 scripts/go-linux.yaml /etc/lanbridge/config.go.yaml
sudo install -m 644 scripts/lanbridge-go.service /etc/systemd/system/lanbridge-go.service
sudo systemctl daemon-reload
sudo systemctl start lanbridge-go
sudo systemctl status lanbridge-go --no-pager
curl -k https://127.0.0.1:8766/healthz
```

`-k` здесь только диагностирует локальный самоподписанный TLS, не настраивает доверие.
Создайте администратора и файл в браузере, выполните `sudo systemctl restart lanbridge-go`,
проверьте сохранность. Завершите `sudo systemctl stop lanbridge-go`.

**Ожидается:** active (running), healthz успешен, данные сохраняются после restart,
штатный stop без зависания. Пакеты ping/traceroute нужны для соответствующей диагностики.
**При ошибке:** `systemctl status` и `sudo journalctl -u lanbridge-go -n 100 --no-pager`,
дистрибутив и архитектура. Если браузер на другом ПК — настройте LAN-доступ по разделу 2.

## 9. Docker на Linux

Нужны Docker Engine и Compose plugin. Из корня проекта, на свободном порту 8766:

```sh
docker compose -f docker-compose.go.yml build
docker compose -f docker-compose.go.yml up -d
docker compose -f docker-compose.go.yml ps
curl -k https://127.0.0.1:8766/healthz
```

Создайте администратора и тестовый файл в браузере на хосте. Затем:

```sh
docker compose -f docker-compose.go.yml restart
docker compose -f docker-compose.go.yml logs --tail=100
docker compose -f docker-compose.go.yml down
```

Перед `down` проверьте сохранённые вход и файл. Не добавляйте `-v`: тома с данными
должны сохраниться. Порт по умолчанию доступен только на хосте.
**Ожидается:** контейнер работает без privileged, файл переживает restart,
внешний туннель выключен. LAN-обнаружение из bridge-сети ограничено.
**При ошибке:** версии Docker/Compose, `ps`, последние 100 строк логов и ошибка сборки.

## 10. Суточная проверка и завершение приёмки

Выполните [release-soak.md](release-soak.md): Windows `scripts/soak-24h.ps1`,
Linux `sh scripts/soak-24h`. Не закрывайте терминал и не допускайте сна 24 часа.
**Ожидается:** result PASS, full_day true, memory.verdict STABLE и непрерывный CSV.
**При ошибке:** весь каталог отчёта и время сна/перебоя, если они были.

Для SIGTERM на Linux после установки Python с зависимостями тестов:
`python3 scripts/verify_go_shutdown.py dist/lanbridge-linux-amd64`.
Ожидается PASS и integrity_check=ok; при ошибке пришлите traceback и ОС.

Пришлите таблицу разделов 1–10 с результатами и отдельное подтверждение суточного
прогона. Только после этого может быть поставлен окончательный тег `v0.1.0`.
