# Проверка выпуска и документации

[README](../README.md) · [CHANGELOG](../CHANGELOG.md)

Проверки выполняются на Windows 11, Python 3.14.4, Node 24.15.0. Версия проекта — `0.1.0-dev.1`. Тесты используют временные каталоги и сессии; существующая рабочая база при оформлении репозитория сохранена.

## Воспроизводимые проверки

| Проверка | Команда Windows | Назначение |
|---|---|---|
| Установка | `python run.py --install-only` | Создание среды и runtime-зависимостей |
| HTTPS smoke | `python run.py --check` | Новый сервер, пустая БД, TLS, frontend, OpenAPI; после проверки процесс завершается |
| Unit | `python run.py --test` | Возобновление/сборка/хеш, отсутствие частей, пути, symlink, расширения |
| Ruff | `python run.py --lint` | Python после установки dev-зависимостей |
| Репозиторий | `python scripts/check_repository.py` | Индекс Git, приватные файлы и известные форматы ключей |
| Документация | `.venv\Scripts\python.exe scripts/check_docs.py` | Внутренние ссылки, изображения, полнота таблицы YAML |
| API | `.venv\Scripts\python.exe scripts/verify_api.py` | Сессии, CSRF, роли, чанки, Range, guest, выключенный туннель |
| Обрывы и UI | `.venv\Scripts\python.exe scripts/verify_disconnects.py` | WebSocket, навигация, темы, перезагрузки, 40 TCP RST и отсутствие ошибок в журнале |
| UI | `.venv\Scripts\python.exe scripts/screenshots.py` | Реальный Chromium, навигация, API-пример, четыре снимка и проверка ширины |

До Ruff/UI/API-проверок устанавливаются dev-зависимости; до первого UI-прогона — Chromium через Playwright. Команды приведены в [README](../README.md). Сценарий HTTPS smoke выполняется перед каждым коммитом, в том числе перед фиксацией merge.

## Чистый клон

Из папки, содержащей локальный репозиторий:

```powershell
git clone --no-local .\lanbridge .\lanbridge-clean
cd .\lanbridge-clean
python run.py
```

В клоне не должно быть прежней `.venv`, рабочего `config.yaml`, `.env`, базы, сертификатов и файлов пользователей. Первый запуск создаёт их заново. Сервер должен отвечать на `/api/status` с `setup_required:true`, показывать форму создания администратора и успешно обслуживать интерфейс после настройки. Порт должен быть свободен; оригинальный экземпляр на это время остановлен.

Чистый локальный клон проверен на Windows: создание среды, установка зависимостей, запуск HTTPS, создание администратора, загрузка файла через интерфейс и API-пример прошли. Команды выше описывают тот прогон и предполагают существование исходной папки `lanbridge`; для обычного запуска из готовой папки клонирование не требуется.

## Регрессия Windows от 9 октября 2026

- После исправления очистки Proactor-транспорта прошли 14 unit-тестов и Ruff.
- API-прогон проверил сессии, CSRF, роли, защиту путей, докачку, SHA-256, Range, пароль/истечение/отзыв гостевых ссылок и отказ запуска отсутствующего cloudflared. В журнале тестового сервера нет ERROR или traceback.
- Проверены HTTPS smoke и запуск/остановка dev-сервера на Windows.
- Chromium: шесть разделов интерфейса, две темы при ширине 1440 и 390 px, получение WebSocket-сообщений, восемь перезагрузок страницы и 40 принудительных TCP RST. Последующие запросы успешны; серверный журнал без ERROR и traceback.
- Синтаксис `frontend/app.js`, `frontend/auth.js` и `frontend/guest.js` проверен через `node --check`.
- Эти прогоны выполнялись на временных данных и не изменяли рабочие учётные записи или файлы.

## Границы проверки

- PowerShell-обёртки выполнены; `.sh` выполнены в Git Bash на Windows. Это не проверка ядра или окружения Linux.
- В WSL отсутствуют дистрибутивы; Docker CLI/Engine отсутствует. Compose YAML разобран, но image build, healthcheck, namespace и volume permissions ещё не проверены на Docker.
- Обработан сценарий отсутствующего cloudflared. Реальный внешний туннель и отключение из независимой сети не проверены.
- Мобильные снимки означают viewport 390 px в Chromium; физический телефон и второй ПК с файлом 5+ ГиБ пока не испытаны.
- Проверка секретов ограничена индексом и несколькими узнаваемыми шаблонами; независимый аудит безопасности не выполнен.

## Порядок релиза

1. Закрыть перечисленные критерии внешнего доступа, большого файла, ОС и безопасности; записать окружение и результаты.
2. Перенести изменения из `feature/*` в `dev`, затем проверенное состояние в `main`.
3. Обновить VERSION до `0.1.0`, перенести Unreleased в датированный раздел CHANGELOG, пройти README из нового чистого клона.
4. После успешного запуска зафиксировать выпуск и поставить тег `v0.1.0`.
5. Публикация remote и push выполняются только по отдельной команде владельца. Пока этих условий нет, версия остаётся предварительной и релизный тег не создаётся.
