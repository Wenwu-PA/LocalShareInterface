# Устройства и диагностика Go-версии

Откройте «Устройства» на `https://localhost:8766/#devices`. Администратор выбирает
IPv4-подсеть и запускает сканирование; обычный пользователь может просматривать
результаты и историю. Автоматическое сканирование выключено до явного включения.

## Сканирование

Допускаются только частные IPv4-адреса на активных интерфейсах сервера: от `/24`
до `/32`, не более 256 адресов за запуск. Для интерфейса с более широкой маской
предлагается `/24`, содержащая его адрес. Сети вне этого диапазона отклоняются.
Для проверки одного устройства укажите, например, `192.168.1.10/32`.

ICMP: четыре запуска в секунду, до четырёх одновременно, таймаут одной цели
одна секунда. Используется системный `ping`. Затем читается таблица соседей
(`arp -a` на Windows, `ip neigh show` на Linux) и выполняется короткий mDNS-запрос.
Один запуск ограничен двумя минутами. Кнопка «Отменить» останавливает работу;
неполный результат не заменяет предыдущую картину сети.

mDNS использует запросы PTR и ответы A на локальном IPv4-интерфейсе, включая
обратные запросы к уже найденным адресам и перечисление сервисов. Принимаются
ответы только из выбранной подсети, UDP-порт 5353. Подход с временным исходящим
портом описан в [RFC 6762, раздел 6.7](https://www.rfc-editor.org/rfc/rfc6762.html#section-6.7).
Полноценного IPv6-обнаружения пока нет.

| Статус | Что означает |
|---|---|
| В сети | Получен ICMP/mDNS-ответ либо это собственный активный адрес сервера |
| Не подтверждён | Адрес найден в ARP-кэше, но свежего ответа нет |
| Не отвечает | Ранее найденное устройство не обнаружено при последнем полном запуске |

Брандмауэр, спящий режим и блокировка multicast могут скрывать работающие устройства.
Эти статусы не доказывают физическое отключение оборудования. Пользовательское имя,
значок и отметка «Известное» сохраняются. История смены статуса хранится до года,
очищается после успешного сканирования; интерфейс показывает 100 последних событий.
При наличии MAC идентичность сохраняется при смене IP. Случайные MAC могут создавать
новые записи, а без MAC изменение IP не всегда можно связать с прежним устройством.

Расписание: 120–86400 секунд между запусками. Новый запуск не начинается, пока
предыдущий не завершён. На странице устройств — поиск, фильтр и страницы по 50 строк.
API возвращает до 10 000 последних устройств.

## Производители

В бинарник встроена сжатая таблица **20 префиксов**, перенесённая из Python-версии.
Это неполный справочник, не актуальный полный реестр. Локально назначенный MAC
помечается отдельно. Неизвестный производитель не угадывается.

Скрипт `scripts/update_oui.py` предназначен для обновления из публичного
[CSV IEEE MA-L](https://standards-oui.ieee.org/oui/oui.csv). При работе 10 октября
2026 года источник отвечал HTTP 418; обновление полного справочника не выполнено.
Сервер сам ничего из интернета не скачивает.

## Уведомления

В настройках канала включите «Сообщать о новом устройстве». Событие `device`
ставится в ту же надёжную очередь при первом сохранении устройства. Оно не
повторяется при каждом сканировании. Отметка «Известное» служит для ручного учёта;
первое появление ещё не отмеченного устройства считается новым.

## Диагностика

На той же странице доступны:

- Ping: четыре проверки с сервера, время и результат каждой.
- TCP-порт: `host:port`, попытка подключения с сервера.
- DNS: адреса имени через резолвер сервера.
- Traceroute: `tracert` на Windows, `traceroute` на Linux; максимум 12 переходов.
- Скорость LAN: загрузка 16 МиБ в браузер без сохранения файла. Это скорость
  сервер → клиент; на том же компьютере измеряется loopback, а не Wi-Fi.

Операции доступны администратору; максимум две одновременно, потоковый результат,
отмена через AbortController и контекст серверного запроса. Диагностика ограничена
45 секундами, замер загрузки — 30 секундами. Отдельный upload-тест пока не реализован.
На Linux `traceroute` может потребовать отдельной установки. Локализованный вывод
Windows tracert с не-UTF-8 кодировкой пока может содержать `?`; числовые адреса
и времена сохраняются.

## API

| Метод | Путь | Доступ / назначение |
|---|---|---|
| GET | `/api/devices` | Сессия; устройства, интерфейсы, прогресс, расписание |
| POST | `/api/devices/scan` | Администратор + CSRF; `subnet` |
| POST | `/api/devices/cancel` | Администратор + CSRF |
| POST | `/api/devices/config` | Администратор + CSRF; `enabled`, `subnet`, `interval` |
| PUT | `/api/devices/{id}` | Администратор + CSRF; `name`, `icon`, `known` |
| GET | `/api/devices/{id}/events` | Сессия; история присутствия |
| POST | `/api/diagnostics` | Администратор + CSRF; `kind`, `target`; NDJSON-поток |
| GET | `/api/diagnostics/speed` | Администратор; 16 МиБ, `no-store` |

## Проверка

Go-тесты проверяют разбор ARP разных ОС, ограничения подсетей, mDNS-пакеты,
сохранение идентичности при смене IP/отсутствии MAC, историю, роли и TCP-диагностику.
Браузерный сценарий `scripts/verify_go_ui.py` сканирует только собственный адрес
сервера `/32`, меняет имя/отметку устройства и проверяет TCP/скорость на loopback.
Полный обход физической подсети, разные модели телефонов/роутеров и Linux
не считаются проверенными этими тестами.

## Сводка в обзоре

Карточка «Устройства сети» показывает ответившие и все обнаруженные устройства,
число неответивших, неподтверждённых и неотмеченных знакомыми, время последнего
сканирования и состояние автопоиска. Это сохранённые результаты обнаружения,
а не непрерывный контроль доступности: при выключенном автопоиске они стареют.

`GET /api/devices/summary` доступен вошедшим пользователям и вычисляет счётчики
в SQLite без загрузки списка устройств и без запуска сканирования. Поля:
`total`, `online`, `offline`, `unknown`, `unrecognized`, `last_scan`, `enabled`,
`error`. Ограничение времени SQL-запроса — 3 секунды.
Карточка обновляется каждые 30 секунд в видимой вкладке, по завершении сканирования
и при возврате во вкладку; ошибка обновления явно отмечается рядом со старыми данными.
