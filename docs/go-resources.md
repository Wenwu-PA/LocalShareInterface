# Ресурсы сервера и предупреждения

Администратор видит предупреждения на всех страницах Go-интерфейса. В обзоре
дополнительно показаны размер основной БД, свободные страницы, размер WAL,
свободное место хранилища/диска БД, CPU и память процесса. Windows: рабочий набор
(working set) и Private commit; Linux: RSS. Отдельно показана занятая куча Go,
которая не равна всей памяти процесса. Рабочий набор/RSS может включать общие
страницы; Private commit включает выделенную процессу память, даже не находящуюся
сейчас в RAM. Метрики относятся только к процессу LANBridge, без ОС и cloudflared.

CPU — разность пользовательского и системного времени процесса между замерами,
делённая на прошедшее время. 100% означает одно занятое логическое ядро, при
параллельной работе возможно больше 100%. Первый замер не имеет процента — нужны
две точки. Минимальный интервал — одна секунда; запросы чаще используют общий кеш.
В карточке показан фактический интервал. Это средняя нагрузка между замерами,
а не мгновенный пик. Метрики не сохраняются в БД.

Windows использует GetProcessTimes и [GetProcessMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo)
со структурой [PROCESS_MEMORY_COUNTERS_EX](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex).
Linux использует getrusage и /proc/self/statm; Private commit там не выдаётся.
Общая загрузка CPU/памяти всего компьютера пока не собирается.

`GET /api/resources` требует сессию администратора; обычный пользователь получает
403, а гостевой внешний шлюз блокирует этот маршрут. В ответе нет путей runtime.
Интерфейс запрашивает состояние раз в 30 секунд, только в видимой вкладке, и при
возвращении к ней. Ошибка обновления явно помечает прошлые измерения устаревшими.

## Пороги

| Ресурс | Предупреждение | Критическое состояние |
|---|---|---|
| SQLite | Занято ≥90% `database.max_mb` | Занято ≥98% |
| Диск файлов | Свободно ≤max(1 ГиБ, 3 × резерв) | Свободно ≤`critical_free` |
| Диск БД | Свободно ≤max(1 ГиБ, 3 × запас) | Свободно ≤размер БД + 64 МиБ |

Для SQLite занятое место считается как `(page_count − freelist_count) × page_size`:
освобождённые страницы можно использовать повторно, даже если файл не уменьшился.
WAL не входит в лимит основной БД. Запас диска БД рассчитан под ещё одну резервную
копию и небольшой WAL; это предупреждение, а не гарантия места для любой операции.
Файлы и runtime могут находиться на разных дисках — они измеряются независимо.
Если ОС не дала измерение, интерфейс показывает «Нет данных», а не здоровое состояние.

Сервер также проверяет ресурсы при старте и раз в минуту. В ротируемый JSON-журнал
попадают изменения уровня тревоги (`resource warning`) и нормализация
(`resource warning cleared`). Повтор неизменившегося состояния не записывается.
Ошибка измерения не выдаётся за восстановление ранее проблемного ресурса.
Доставка этих тревог через Telegram/SMTP/Webhook пока не подключена.

Проверено: граничные пороги, повторное использование свободных страниц при оценке,
роли API, отсутствие повторных сообщений в журнале. В браузерном сценарии резерв
временно увеличивается выше реального свободного места на тестовом сервере:
проверены появление/исчезновение тревоги, карточки, desktop/mobile и отсутствие
ошибок JS. Диск компьютера тест не заполняет.

```powershell
.venv\Scripts\python.exe scripts/verify_go_files.py
```


Дополнительно проверены расчёт CPU (включая >100%), отсутствие результата при
первом замере/сбросе счётчика, чтение реального процесса Windows и кеширование.
`scripts/verify_go.py` сравнивает рабочий набор и Private commit API с psutil;
допуск 8 МиБ или 20% учитывает разные моменты измерения и работу сборщика мусора.
Linux-реализация проходит кросс-сборку, но ещё не проверена на работающем Linux.
