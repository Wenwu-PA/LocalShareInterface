# Безопасность

[README](../README.md) · [Архитектура](architecture.md) · [Внешний доступ](external-access.md)

## Модель угроз

| Угроза | Реализованная защита | Граница защиты |
|---|---|---|
| Чтение файлов за пределами share | Нормализация, проверка resolved path, запрет symlink/служебных путей | Не защищает от администратора ОС и конкурентной подмены файлов локальным процессом |
| Перебор пароля | Argon2, окно попыток по IP, HTTP 429, предупреждения | Нет распределённой защиты от большого числа IP и глобального DoS-лимита |
| Чужой изменяющий запрос | Cookie + связанный с сессией CSRF, проверка Origin, отсутствие разрешённого cross-origin API | XSS или контроль браузера/ОС находятся за этой границей |
| Перехват по LAN | HTTPS, возможность доверенного собственного сертификата | Автоматический self-signed сертификат нужно проверить и доверить вручную |
| Утечка гостевой ссылки | Случайный токен, SHA-256 токена в БД, TTL, лимит, пароль и отзыв | URL является bearer-секретом; уже скачанную копию отозвать нельзя |
| Заполнение диска | Лимит одного файла, потоковая запись, предупреждение о свободном месте | Нет квот по пользователям, антивируса и защиты от множества загрузок |
| Случайная внешняя публикация | Управляемый cloudflared выключен при старте; direct public peer отклоняется | Firewall, VPN, proxy и маршрутизатор настраиваются отдельно |

Независимый аудит безопасности не выполнен. Наличие тестов не является подтверждением отсутствия всех критичных уязвимостей. Перед публичным использованием нужна проверка всей схемы развёртывания.

## Роли и первая настройка

| Возможность | admin | user | guest |
|---|---|---|---|
| Файлы общей папки, включая изменение/удаление | Да | Да | Только чтение выбранного объекта ссылки |
| Создание ссылок | Да | Да | Нет |
| Список ссылок | Все | Созданные этим пользователем | Нет |
| Отзыв ссылок | Да | Нет | Нет |
| История передач | Общая | Собственная | Нет |
| Метрики и диагностика | Да | Да | Нет |
| Общий аудит, пользователи, туннель | Да | Нет | Нет |

Первый посетитель незаполненной базы может создать администратора. Выполняйте первоначальную настройку в доверенной сети или сначала привяжите сервер к `127.0.0.1`. Начальных паролей и скрытых учётных записей в репозитории нет. После клонирования база создаётся заново; при переносе рабочей базы существующие пользователи сохраняются.

`user` — доверенный участник общей папки, а не изолированный владелец собственных файлов. Для временного получателя используйте guest-ссылку. Смена пароля в настройках отзывает другие сессии этой учётной записи; текущая остаётся действующей.

## Сессии и запросы

В браузере хранится случайная cookie `lanbridge_session`. SQLite содержит SHA-256 сессионного токена, срок и связанный CSRF-хеш. Cookie имеет `HttpOnly`, `SameSite=Strict`; `Secure` установлен при включённом HTTPS. Срок по умолчанию — семь дней.

`lanbridge_csrf` доступна JavaScript: клиент переносит её значение в `X-CSRF-Token` для POST/PUT/DELETE. Заголовок проверяется по cookie и сессии; при наличии Origin он должен совпадать с адресом запроса. Setup, login и ввод пароля гостя тоже требуют bootstrap CSRF-cookie с главной/гостевой страницы. WebSocket проверяет сессию и Origin до принятия соединения.

Ограничение обычного логина задаётся конфигурацией: по умолчанию восемь неудачных попыток за 15 минут. Для пароля гостевой ссылки действует отдельное фиксированное ограничение 8/15 минут. Ограничение применяется к видимому серверу IP; за NAT/proxy несколько людей могут получить общий лимит.

## Внешняя граница

Управляемый Cloudflare-процесс подключается к HTTPS loopback-origin. Для самоподписанного origin используется отключение проверки его сертификата; внешнее соединение браузера с Cloudflare остаётся отдельным TLS-соединением. Cloudflare является доверенным посредником обработки внешнего трафика. Для строгой проверки origin потребуется отдельная схема с доверенным сертификатом и настроенным туннелем.

Прямые запросы с публичных адресов отклоняются. Частные, loopback, link-local и CGNAT-адреса считаются локальными. Заголовки Cloudflare интерпретируются как внешние только при активном управляемом туннеле и loopback-peer. Процесс, уже имеющий доступ к localhost, не считается изолированным противником.

Reverse proxy и Docker NAT могут скрывать публичный IP за локальным peer, поэтому фильтр приложения **не гарантирует закрытый интернет-доступ** при произвольном пробросе портов. Нельзя полагаться на положение UI-переключателя для VPN, независимого cloudflared, Nginx или роутера. Их жизненный цикл, firewall и аудит нужно обеспечивать отдельно; управляемые NetBird/proxy адаптеры не реализованы.

Публикация Quick Tunnel открывает маршруты приложения, включая страницу входа. Права guest-ссылки ограничены файлом/каталогом, но отдельной публичной гостевой подсистемы с закрытым admin-origin пока нет. `/docs` и схема API также доступны без сессии; сами защищённые операции проверяют доступ.

## Аудит и чувствительные данные

Аудит хранит время, actor, действие, путь/объект, IP и краткие подробности. Записываются входы и ошибки входа, файлы/передачи, гостевой доступ, создание/отзыв ссылок, пользователи, изменения пароля, диагностика и управление туннелем. Внешние запросы через управляемый туннель получают отдельные записи; bearer-токен в их audit-path маскируется.

HTTP access-log Uvicorn может содержать URL гостевой ссылки, а console/debug-логи внешнего proxy имеют собственные правила. Не публикуйте эти логи без удаления URL-токенов, IP и путей. Пароли и cookie нельзя добавлять в README, issue, снимки интерфейса и Git. `.gitignore` исключает стандартные места хранения; нестандартные каталоги вне `data` должны иметь отдельные правила.

Проверка `scripts/check_repository.py` анализирует индекс Git и наиболее узнаваемые ключи, но не может распознать любой секрет. Перед коммитом просматривайте `git status` и staged diff.

## Резервная копия и обновление

Остановите сервер штатно. Скопируйте всю папку `data`, рабочий `config.yaml` и `.env` в защищённое хранилище; при остановленном процессе сохраняйте также существующие SQLite WAL/SHM-файлы. Резервная копия содержит пользовательские данные, хеши паролей, сессионные токены в виде хешей и TLS private key. Она не должна попадать в Git.

Для восстановления верните данные и конфигурацию до запуска. При изменении путей перенесите сами файлы отдельно. Не запускайте одновременно оригинал и копию с общей SQLite-базой. Перед доступом извне проверьте права каталога, роль каждой учётной записи, активные ссылки и firewall.
