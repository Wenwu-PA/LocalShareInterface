# Файлы в Go-версии

Файловый модуль работает в отдельной Go-версии на порту 8766. Запуск и сборка:
[go-foundation.md](go-foundation.md). Корень задаётся `storage.root` в
`config.go.yaml`; относительный путь считается от каталога конфигурации.
Данные старого Python-приложения автоматически не подключаются.

## Использование

Откройте «Файлы». Создавайте вложенные папки, загружайте файлы или папку,
перетаскивайте каталоги в список. Перетаскивание через поддерживаемый браузером
`webkitGetAsEntry` сохраняет пустые папки. Диалог «Загрузить папку» использует
`webkitdirectory`: пустые каталоги этот интерфейс браузера не передаёт.

Нажатие на папку открывает её содержимое, хлебные крошки возвращают выше.
Слева находится сворачиваемое дерево папок; на узком экране оно расположено над
списком. Кнопки «+»/«−» раскрывают ветку, имя открывает папку. На каждом уровне
раскрыта одна ветка; её подпапки запрашиваются только при раскрытии, по 50 на
страницу. «Назад»/«Далее» листают папки, «Обновить дерево» перечитывает корень.
После файловых операций дерево обновляется этой кнопкой. Фильтрация прав и
выбор только папок выполняются на сервере до пагинации. Поиск
выполняется по именам во всём доступном хранилище. Сортировка: имя, размер, дата; порядок — по возрастанию или убыванию.
Папки остаются перед файлами в обоих направлениях.
API отдаёт до 500 объектов за запрос; «Загрузить ещё» добавляет следующую страницу.
Переключатель «Вид файлов» выбирает список или плитки. Выбор сохраняется
в этом браузере отдельно для каждой учётной записи; при недоступном localStorage
переключение продолжает работать без сохранения. В DOM находятся не более
18 строк списка либо 7 рядов плиток (до 35 карточек). Число колонок адаптируется
к ширине экрана; при смене вида и ширины сетки прокрутка сбрасывается.
Проверено переключение и прокрутка 1104 объектов на desktop и при ширине 390 px.

Имя файла запускает скачивание с HTTP Range. Для ZIP отметьте файлы/папки и
нажмите «Скачать ZIP». «Выбрать загруженные» отмечает уже полученные объекты
(не только видимые строки); для списка длиннее 1000 выбираются первые 1000.
«Снять выбор» очищает отметки. Новые страницы автоматически не выделяются.
При слишком большом общем списке имён ZIP недоступен до сокращения выбора;
можно выбрать родительскую папку. После обновления отметки отсутствующих
в полученном списке объектов сбрасываются. Сервер передаёт архив потоком без промежуточного файла,
браузер сохраняет его штатным механизмом загрузки. Вложенные и пустые каталоги
сохраняются; повторно выбранные вложенные элементы не дублируются. ZIP использует
метод Store без сжатия, чтобы не расходовать CPU на уже сжатые медиафайлы.

Меню «••• → Предпросмотр» открывает текст UTF-8 (первые 64 КиБ), изображения
PNG/JPEG/GIF/WebP/AVIF/BMP и видео в форматах, поддерживаемых браузером.
HTML/XML показываются как текст, без исполнения. Для других форматов остаётся
скачивание. Видео запрашивает метаданные и использует HTTP Range.

Меню «•••»: перемещение/переименование, копирование, корзина и права доступа для
администратора. Целевой путь перемещения и копирования указывается относительно
общего корня, например `Документы/Отчёт.txt`; целевая родительская папка должна
существовать. Конфликт имени: отказ, сохранение обоих или замена. При замене через
операции копирования/перемещения старый объект попадает в корзину. Замена при
загрузке перезаписывает старый файл после проверки SHA-256, без сохранения версии.

## Передачи и восстановление

- Очередь: две параллельные передачи, части по 1 МиБ, серверный буфер 64 КиБ.
- SHA-256 считается до передачи в Web Worker, по частям без загрузки целого файла
  в память. После получения сервер повторно проверяет весь файл.
- Сервер подтверждает смещение после записи и `Sync`; лишний хвост незавершённой
  части отбрасывается перед повторной записью. Данные передачи сохраняются в SQLite.
- При паузе, уходе с экрана, перезагрузке страницы или ошибке соединения передачу
  можно продолжить вручную. После перезагрузки выберите исходный файл заново:
  размер и SHA-256 должны совпасть. Браузер не сохраняет содержимое файла в localStorage.
- Публикация имеет состояние `committing`: после сбоя сервер повторяет проверку и
  завершает публикацию. Журнал перемещений и копирований хранит намерение операции,
  целевой путь и снимок прав. Неоднозначное состояние требует проверки администратором;
  сервер пишет ошибку и не пытается угадать, какие данные удалить.
- Докачка по умолчанию хранится 72 часа с последней подтверждённой части.
  Просроченные части удаляет обслуживание каждые 30 секунд.

Публикация без замены использует жёсткую ссылку внутри хранилища и атомарную
проверку отсутствия целевого имени. Требуется файловая система с поддержкой hard link
(например NTFS или ext4). FAT/exFAT для этой версии не поддерживаются.

## Права и квоты

Режимы: `users` — чтение и запись для пользователей; `read` — только чтение для
пользователей; `admin` — только администратор. Администратор управляет всем корнем.
Ближайшее правило наследуется вложенными путями; перемещение/копирование сохраняет
снимок правил и не ослабляет ограничения назначения. Временные состояния переноса
и восстановления закрыты от обычных пользователей до завершения журнала.

Проверяются выход за корень, символические ссылки, зарезервированные Windows-имена,
управляющие символы и неоднозначные пути. Регистр фактических родительских каталогов
проверяется по списку файлов, чтобы Windows-алиасы не обходили права в SQLite.
Служебный каталог `.lanbridge` не доступен через файловый API. Не давайте недоверенным
локальным процессам права изменять хранилище напрямую: веб-права не заменяют права ОС.

Параметры хранятся в SQLite, доступны администратору через `PUT /api/files/storage`.
В интерфейсе администратора откройте «Файлы → Настройки хранилища».
Размеры вводятся в МиБ, сроки — в днях и часах. Форма проверяет границы и
сохраняет все шесть параметров; при ошибке введённые значения остаются в форме.

| Параметр | По умолчанию | Значение |
|---|---:|---|
| `global_limit` | 0 | Общая квота, байты; 0 — без ограничения |
| `user_limit` | 0 | Квота одного владельца, байты; 0 — без ограничения |
| `critical_free` | 67108864 | Резерв свободного диска; минимум 16 МиБ |
| `trash_days` | 30 | Срок корзины, 1–365 дней |
| `trash_limit` | 1073741824 | Лимит корзины, байты; 0 — без ограничения по размеру |
| `partial_hours` | 72 | Срок незавершённых загрузок, 1–720 часов |

Квоты учитывают индекс и зарезервированные размеры активных загрузок. Файлы,
добавленные вне приложения, появляются после очередного индексирования (30 секунд).
Для внешних файлов владелец неизвестен: они учитываются в общей квоте, но не в
пользовательской. Корзина очищается по сроку и затем от старых элементов при
превышении лимита. Большой файл, превышающий лимит корзины, может быть удалён уже
при ближайшем обслуживании. Корзина не заменяет резервную копию файлов.

## API

Все маршруты требуют сессии. Изменения требуют `X-CSRF-Token`; JSON — заголовка
`Content-Type: application/json`. Подробнее об авторизации: [go-foundation.md](go-foundation.md).

| Метод и маршрут | Назначение |
|---|---|
| `GET /api/files?path=.&q=&sort=name&order=asc&offset=0&limit=500` | Список с фильтрацией прав до пагинации |
| `GET /api/files?path=.&folders=1&offset=0&limit=50` | Только доступные подпапки для дерева |
| `GET /api/files/download?path=Документы/Отчёт.txt` | Скачивание, HTTP Range |
| `POST /api/files/mkdir` | `{ "path": "Фото/Пустая" }` |
| `POST /api/files/operation` | `action`: move/copy/trash, `source`, `target`, `conflict`: skip/both/replace |
| `POST /api/files/zip` | Потоковый ZIP; JSON `paths` |
| `POST /api/files/zip-ticket` | Одноразовый URL ZIP на 60 секунд, привязанный к сессии |
| `GET /api/files/zip/{ticket}` | Штатное браузерное скачивание ZIP; права проверяются повторно |
| `GET /api/files/trash` | Последние 1000 объектов корзины, свои или все для администратора |
| `POST /api/files/restore` | `id`, `conflict` |
| `GET /api/files/storage` | Квоты, объём файлов, свободное место |
| `PUT /api/files/storage` | Все параметры таблицы выше, только администратор |
| `PUT /api/files/access` | `path`, `access`: admin/read/users |
| `GET /api/uploads` | Свои незавершённые загрузки |
| `POST /api/uploads` | `path`, `size`, `sha256`, `conflict` |
| `GET /api/uploads/{id}` | Состояние и подтверждённый `offset` |
| `PATCH /api/uploads/{id}` | Бинарная часть 1–1048576 байт, заголовок `Upload-Offset` |
| `POST /api/uploads/{id}/finish` | Проверка и публикация файла |
| `DELETE /api/uploads/{id}` | Отмена до начала публикации |
| `GET /api/transfers` | Последние 200 завершённых загрузок |

## Проверки и текущие границы

Проверено на Windows: модульные тесты путей, наследования прав, Windows-регистра,
пагинации, докачки, квот, контрольных сумм, ZIP, корзины и восстановления журнала;
API-тест загрузки/Range/ZIP/корзины; Chromium: загрузка 1 800 000 байт, сравнение
скачанного содержимого, копирование/восстановление, докачка после перезагрузки,
отказ для другого SHA-256, 1104 объекта при максимум 18 строках DOM. Четыре
[скриншота](previews/index.html): две темы, desktop/mobile. Ошибок JavaScript и
горизонтального переполнения в этом прогоне нет.

```powershell
.\build.ps1
.venv\Scripts\python.exe scripts/verify_go_files.py
```

Скрипты проверки используют Python с Playwright/psutil и временные каталоги;
это зависимости разработки, исполняемому Go-приложению они не нужны.

Остаются: перетаскивание файлов в дерево, предпросмотр PDF и других документов,
временные гостевые ссылки/QR, история скачиваний и автоматические уведомления о
нехватке места. Процесс копирования пока сериализует изменения метаданных; при
больших каталогах операции создания/перемещения могут ожидать завершения копии.
Это промежуточный этап, не финальная готовность проекта.

## Передача 20 ГиБ

Проверка 11 октября 2026 года, Windows, HTTPS loopback, временное NTFS-хранилище:
21 474 836 480 байт записаны на диск сервера и затем скачаны полностью. SHA-256
совпал. После 256 МиБ процесс принудительно завершён, повторный запуск подтвердил
смещение и принял оставшиеся части. Клиент держал один блок 1 МиБ, серверный буфер
передачи — 64 КиБ. Это API-прогон, не браузерная передача 20 ГиБ по физической LAN.

| Измерение | Результат |
|---|---:|
| Загрузка, включая перезапуск | 52,87 с |
| Серверная проверка SHA-256 и публикация | 13,15 с |
| Полное скачивание с SHA-256 на клиенте | 70,73 с |
| Максимальный наблюдавшийся working set | 54 091 776 байт |
| Максимальные наблюдавшиеся Private Bytes | 87 834 624 байта |

Память снималась каждые 64 МиБ передачи, поэтому это выборочный максимум, а не
непрерывный профиль всех пиков. Private Bytes превышают 60 МБ; физический working
set в этом прогоне укладывается. Прогон без мониторов не подтверждает бюджет для
одновременной передачи и 50 проверок. Нагрузочное испытание 24 часа ещё не проведено.

Команда требует более 22 ГиБ свободного места во временном каталоге и очищает
свои тестовые данные после завершения:

```powershell
.venv\Scripts\python.exe scripts/verify_go_large_file.py --gib 20
```

Браузерная проверка предпросмотра: текстовый файл 1 800 000 байт, отображение
ровно первых 65 536 байт и закрытие диалога. Видеокодеки отдельно не проверялись.
