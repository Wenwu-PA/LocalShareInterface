# Службы и контейнер Go-версии

Go-бинарник работает в консоли и понимает Windows Service Control Manager.
Остановка службы отменяет задачи, закрывает внешний туннель, завершает HTTP и
делает checkpoint БД. Бинарник сообщает службе состояние Running после подготовки
TLS, открытия порта и запуска работников. Лимит ожидания остановки службы — 30 с.

## Windows

Сначала соберите проект и проверьте запуск в консоли по [быстрому старту](go-foundation.md).
Для постоянной установки используйте отдельный каталог с абсолютными путями.
Бинарник и конфигурация должны быть защищены от записи обычными пользователями;
LocalService нужны чтение бинарника/config/.env.go и изменение runtime/общей папки.
Не предоставляйте службе запись в каталог бинарника или чужие пользовательские папки.
Секреты берутся из `.env.go` рядом с конфигурацией; переменные пользовательского
PowerShell служба не наследует.

Подготовив файлы и права, выполните из корня проекта в PowerShell администратора
(замените пути на действительные):

```powershell
.\scripts\install-go-service.ps1 -Binary 'C:\Program Files\LANBridge\lanbridge.exe' -Config 'C:\ProgramData\LANBridge\config.go.yaml' -WhatIf
.\scripts\install-go-service.ps1 -Binary 'C:\Program Files\LANBridge\lanbridge.exe' -Config 'C:\ProgramData\LANBridge\config.go.yaml'
Start-Service LANBridgeGo
Get-Service LANBridgeGo
```

Создание службы не запускает сервер. Учётная запись — встроенная LocalService,
автозапуск — Automatic. Сетевые папки с пользовательскими учётными данными могут
быть ей недоступны. Рекомендуется локальная общая папка и явные NTFS-права.
Скрипт не меняет ACL, брандмауэр и доверие сертификатам. Ошибки после загрузки
конфигурации пишутся в `storage.data/logs/lanbridge.log`; ошибки самой конфигурации
диагностируйте запуском того же бинарника и аргументов в консоли.

Обновление: остановите службу, сохраните runtime, замените бинарник, запустите службу.
Не запускайте одновременно консольный и служебный экземпляр с одной БД.

```powershell
Stop-Service LANBridgeGo
# После замены бинарника:
Start-Service LANBridgeGo
```

Удаление регистрации с сохранением всех файлов:

```powershell
.\scripts\remove-go-service.ps1 -WhatIf
.\scripts\remove-go-service.ps1
```

При восстановлении БД остановите службу. Выполните локальную проверку с флагом
из [инструкции восстановления](go-database.md#восстановление-при-повреждении),
завершите консольный экземпляр и лишь затем запустите службу.

## Linux / systemd — подготовлено, запуск на Linux ещё не проверен

Поставляются `scripts/lanbridge-go.service` и `scripts/go-linux.yaml`.
Unit рассчитан на отдельного пользователя/группу `lanbridge`, бинарник
`/opt/lanbridge/lanbridge`, конфигурацию `/etc/lanbridge/config.go.yaml`,
runtime `/var/lib/lanbridge` и общую папку `/srv/lanbridge`. Каталоги данных должны
принадлежать `lanbridge`, исполняемый файл и конфигурация — администратору.
При других путях измените одновременно конфигурацию и `ReadWritePaths` unit.

Unit ограничивает запись двумя каталогами, закрывает `/home`, использует приватный
`/tmp` и запрещает получение новых привилегий. Перезапуск после ошибки — через 10 с,
не более трёх запусков за пять минут. После исправления ошибки потребуется сброс
счётчика отказов средствами systemd. Остановка получает до 40 с.

Для ICMP/трассировки нужны системные `ping` и `traceroute`; доступ к ICMP зависит
от `ping_group_range` и политики ОС. Не выдавайте всей службе root ради сканирования.
Cloudflared, если нужен, устанавливается отдельно; его абсолютный путь задаётся
в конфигурации. Не ставьте `-accept-database-recovery` в unit.

## Docker — подготовлено, сборка и запуск ещё не проверены

Отдельные файлы `Dockerfile.golang` и `docker-compose.go.yml` сохраняют существующую
Python-упаковку. Dockerfile собирает Preact и Go 1.27.2 без CGO, запускает бинарник
под UID/GID 10001. Отдельный `Dockerfile.golang.dockerignore` исключает runtime,
секреты, локальные зависимости и данные из контекста сборки.

Compose публикует HTTPS только на `127.0.0.1:8766`, хранит runtime и файлы в двух
именованных томах, делает корневую файловую систему read-only, даёт временный `/tmp`
и снимает capabilities. При переносе сервера нужно сохранять оба тома. Не применяйте
удаление томов к рабочему экземпляру. Увеличение области публикации порта требует
отдельной настройки доверия TLS и брандмауэра.

ICMP и LAN-обнаружение из bridge-сети контейнера могут быть ограничены; добавление
привилегированного режима не является штатным решением. Cloudflared в образ не входит,
поэтому туннель по умолчанию недоступен. Образ содержит CA-сертификаты и системные
ping/ip/traceroute. Параметры по умолчанию можно переопределять переменными
`LANBRIDGE_GO_*`; HTTPS-сертификат генерируется в томе runtime.

## Проверено в текущем окружении

- Windows: консольный запуск нового бинарника, HTTPS, восстановление БД через
  браузер, тесты обмена StartPending/Running/Interrogate/Stop/StopPending и ошибки
  старта; синтаксис PowerShell и `-WhatIf` установщика.
- Кросс-сборка Linux amd64 прошла.
- Реальная регистрация/работа Windows-службы под LocalService ещё не проверена.
- Docker отсутствует, в WSL нет установленного дистрибутива: контейнер и systemd
  требуют отдельного прогона перед выпуском. Конфигурации не означают готовность
  этих способов развёртывания к релизу.

Ручная приёмка релизного кандидата: [шаги и диагностика](manual-checks.md).
