# Внешний доступ в Go-версии

Реализован Cloudflare Quick Tunnel с отдельным локальным шлюзом. По умолчанию
и после каждого перезапуска доступ выключен. Пользователь включает его в разделе
«Внешний доступ» с подтверждением. Управление доступно только администратору
через основной HTTPS-сервер.

## Что доступно снаружи

Только `/s/{token}`, сведения о гостевой ссылке, создание одноразовой кнопки,
скачивание и статические ресурсы интерфейса. Корень `/`, вход/setup, файлы, загрузки,
настройки, диагностика, SSE и управление туннелем закрыты. Перенесённая извне
административная cookie игнорируется. Публичный `/api/status` выдаёт только гостевой
CSRF и `authenticated: false`.

Основной HTTPS-порт не публикуется. Шлюз слушает отдельный случайный порт на
127.0.0.1. Между ним и локальным `cloudflared` используется HTTP; соединение
пользователя с Cloudflare — HTTPS. Шлюз проверяет точный публичный Host и
`X-Forwarded-Proto: https`. Forwarded IP не используется как доверенная личность:
проверка пароля на внешнем шлюзе имеет один общий лимит 10 ошибок за 15 минут.

Все действующие гостевые ссылки становятся доступными через публичный адрес.
Поэтому перед включением проверьте их список, пароли, срок и лимит. Cloudflare
обрабатывает передаваемый трафик. Правила ссылок: [go-shares.md](go-shares.md).

## Настройка и запуск

1. Скачайте `cloudflared` с [официальной страницы](https://developers.cloudflare.com/tunnel/downloads/).
   Сверьте SHA-256 с digest соответствующего release asset GitHub.
2. Укажите путь в `config.go.yaml` и перезапустите LANBridge:

   ```yaml
   external:
     cloudflared: C:/Tools/cloudflared.exe
   ```

   В Linux можно задать `/usr/local/bin/cloudflared`. Имя `cloudflared` без пути
   ищется в PATH. Относительный путь с разделителем считается от конфигурации.
   Переменная `LANBRIDGE_GO_CLOUDFLARED` имеет приоритет над YAML.
3. Создайте гостевую ссылку в «Файлах», сохраните адрес и задайте пароль.
4. Откройте «Внешний доступ», проверьте HTTPS, наличие администратора и хранилища.
   Подтвердите публикацию, нажмите «Включить внешний доступ».
5. После получения URL замените начало сохранённой ссылки на этот адрес, сохраняя
   `/s/…`. При создании новых ссылок публичный адрес появляется в подсказках поля
   HTTPS-адреса. Сам корень публичного адреса возвращает 404.
6. Откройте гостевую ссылку с телефона через мобильный Интернет и проверьте файл.
   Статус «URL получен» подтверждает выдачу адреса процессом, но не проверку WAN.
7. Нажмите «Отключить сейчас». Сначала закрывается шлюз и активные соединения,
   затем завершается процесс. Новое включение выдаёт другой публичный адрес.

Бинарник запускается без shell с аргументами `tunnel --config <временный-файл>
--no-autoupdate --url http://127.0.0.1:<порт>`. Изолированная пустая конфигурация
не меняет пользовательский профиль Cloudflare; переменные LANBRIDGE_, TUNNEL_
и CLOUDFLARE_ не передаются дочернему процессу. Загрузка/обновление бинарника
самим приложением не выполняется.

## Ограничения и диагностика

- Quick Tunnel предназначен для временной проверки: нет SLA, адрес меняется,
  SSE не поддерживается, сервис ограничивает число одновременных запросов.
  [Официальные ограничения](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).
- LANBridge допускает две гостевые передачи одновременно. Скорость и передача
  20 ГиБ через Cloudflare не проверены; локальный результат не переносится на WAN.
- `cloudflared` — отдельный процесс; его RAM/CPU не входят в замеры Go-сервера.
- Если за 45 секунд URL не получен, запуск прекращается. При выходе процесса
  шлюз закрывается; автоматического повторного открытия нет.
- Ошибка «не найден» означает отсутствие исполняемого файла по заданному пути.
  Ошибка привязки процесса означает, что безопасное управление жизненным циклом
  не настроилось; туннель не остаётся открытым.
- В Windows используется Job Object с kill-on-close, проверен аварийный выход
  родителя. Для Linux добавлен `Pdeathsig`, но runtime-проверка на Linux ещё нужна.
  На других ОС гарантирована штатная остановка; аварийное завершение не проверено.
- Ошибки сети Cloudflare, блокировки провайдером, доверие к сертификатам и
  недоступность самого сервиса могут мешать подключению. Полный stdout/stderr
  провайдера не сохраняется, чтобы исключить запись секретных путей.

## NAT / CGNAT

Кнопка «Проверить внешний IP» выполняет один запрос к
`https://www.cloudflare.com/cdn-cgi/trace` с таймаутом 8 секунд, без редиректов,
ответом до 8 КиБ. Это явное сетевое действие; при открытии экрана запрос не идёт.

Введите WAN IPv4 из роутера. Диапазон 100.64.0.0/10 указывает на shared address
space; частный WAN означает вышестоящий NAT, который может принадлежать вашему
второму роутеру. Различие с наблюдаемым IP также может объясняться VPN/прокси.
Совпадение не доказывает, что входящий порт открыт. Без WAN IPv4 вывод неизвестен.
Исходящий Cloudflare Tunnel не требует проброса входящего порта.

## Журнал и API

В памяти хранятся последние 100 завершённых внешних запросов: время, метод,
категория маршрута, код и байты ответа. Секретные токены, пароли, полные пути и
IP гостей не включаются. Счётчики и этот журнал сбрасываются при перезапуске;
создание/остановка туннеля сохраняются в обычном аудите SQLite. История гостевых
передач также сохраняется в SQLite.

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/external | Статус, проверки, счётчики, журнал |
| POST | /api/external/start | provider=cloudflare, confirm_public_guest_access=true |
| POST | /api/external/stop | Немедленное закрытие шлюза |
| POST | /api/external/network | wan_ip: IPv4 роутера или пустая строка |

Все методы требуют административную сессию; POST дополнительно защищён CSRF.
NetBird и SSH представлены общим интерфейсом `tunnels.Provider`, но их запуск
из Go-приложения пока не реализован и элементы выбора отключены.

## Проверка 14 октября 2026

Проверены Go unit/integration-тесты, `go vet`, Windows-сборка, Linux amd64
cross-build и браузерный `scripts/verify_go_external.py`. Тестовый процесс не
соединяется с Cloudflare: Chromium направляет имитацию публичного HTTPS-адреса
на реальный локальный шлюз. Пройдены скачивание, блокировка приватных маршрутов,
остановка, выключенное состояние после перезапуска и завершение дочернего процесса
при принудительном завершении сервера. Проверены мобильная ширина 390 px и desktop.

Официальный `cloudflared 2026.10.0` проверен командами `--version` и `tunnel --help`;
SHA-256 Windows amd64: `86aee4017b26625cee8484c113558f48effa4cd47f7aa05fcf425604e5d2b23c`.
Он сохранён вне репозитория в пользовательском кеше инструментов. Реальный
публичный туннель, запрос определения IP и доступ с мобильного Интернета в этом
этапе не выполнялись. Это остаётся отдельной проверкой перед использованием.

Ручная приёмка релизного кандидата: [шаги и диагностика](manual-checks.md).
