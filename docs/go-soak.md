# Совместная нагрузка мониторинга и файлов

`scripts/verify_go_soak.py` запускает отдельный Go-сервер на свободном loopback-порту,
создаёт временного администратора и локальную HTTP-цель. Рабочая БД, файлы,
сертификаты и порт 8765 не используются. Внешние адресаты и туннели не подключаются.

Параллельно работают HTTP-мониторы и последовательные циклы загрузки/скачивания
файла с проверкой SHA-256. Каждый цикл меняет содержимое; один файл заменяется,
поэтому объём файлового хранилища не растёт с числом циклов. История передач и
измерений накапливается штатно. Данные обрабатываются чанками по 1 МиБ.

## Запуск

Нужны собранный `dist/lanbridge.exe`, Python с `psutil`. Из корня проекта:

```powershell
.\build.ps1
.venv\Scripts\python.exe scripts/verify_go_soak.py --seconds 120
```

Параметры:

| Параметр | По умолчанию | Допустимые значения |
|---|---:|---|
| `--binary` | `dist/lanbridge.exe` | Путь к отдельной копии бинарника для длительного прогона |
| `--seconds` | 120 | 10–604800 секунд, длительность после подготовки |
| `--monitors` | 50 | 1–1000 HTTP-проверок, интервал 20 с, таймаут 5 с |
| `--file-mib` | 8 | 1–256 МиБ за передачу в каждом направлении |
| `--pause` | 2 | 0–60 секунд между циклами |
| `--max-rss-mib` | 0 | 0–65536 МиБ; 0 — без порога, иначе превышение завершает тест с FAIL |

Для суток используется тот же сценарий с `--seconds 86400`; эта длительность
пока не проверена. Процесс работает в текущей консоли; закрытие консоли, сон
компьютера или Ctrl+C прерывают измерение. Сессия обновляется раз в час для
длительного прогона. Начатый цикл завершается перед окончанием теста, поэтому
фактическая длительность может немного превышать выбранную.

## Результаты и ограничения

Сводка текущего или завершённого прогона без обращения к тестовому серверу:

```powershell
.venv\Scripts\python.exe scripts/summarize_go_soak.py .verification/soak-95819fab592a
.venv\Scripts\python.exe scripts/test_summarize_go_soak.py
```

Для другого прогона подставьте каталог из его поля `report`. Сводка показывает
медианы и максимумы по часовым интервалам, число циклов, объём и максимальный
промежуток между измерениями. Незавершённая последняя строка пропускается;
повреждённые полные записи и непоследовательные времена вызывают ошибку.
`full_day_pass` требует PASS, `full_day: true` и не менее 86400 секунд
как в результате, так и в последнем измерении. RUNNING не означает успешное
завершение, даже если процесс остановлен извне: проверяйте свежесть временного ряда.
Сводка сама не объявляет отсутствие утечек.

Отчёты сохраняются в отдельной `.verification/soak-<id>/`:

- `result.json`: состояние RUNNING/PASS/FAIL, длительность, число циклов, объём
  в каждом направлении, SHA-256 бинарника, Git-ревизия, выборочный пик Working Set/Private Bytes и CPU одного ядра.
- `samples.jsonl`: каждые примерно 10 секунд память, куча, горутины, SQLite/WAL.
- `server-tail.log`: последние 100 строк журнала для диагностики.

После завершения тестовый процесс останавливается, временное хранилище удаляется,
отчёты остаются. Требуется место на две копии выбранного файла плюс 1 ГиБ.
Скрипт проверяет совпадение хеша, корректное завершение загрузок, доступность
всех мониторов и отсутствие ошибок в журнале. PASS подтверждает эти проверки
только за фактическое окно. Без `--max-rss-mib` он не означает прохождение бюджета памяти, отсутствие
долговременных утечек или стабильные 60 fps; браузер в этом сценарии не участвует.
Для оценки утечек нужны длительный прогон и анализ временного ряда. Суточным
считается только отчёт с `full_day: true`, полученный после фактических 86400 секунд.

Этот сценарий не имитирует обрыв физической сети, заполнение диска или реальный
внешний сервис. Все запросы остаются на компьютере, TLS-клиент принимает временный
сертификат тестового сервера. Проверка доверия сертификату телефона выполняется отдельно.
