# Go-версия: запуск и разработка

Разрабатывается рядом с Python-версией. Исполняемый файл: `dist/lanbridge.exe`.
Python-версия продолжает запускаться через `python run.py` и использует свою БД.

## Запуск Windows

Для сборки нужны Go 1.27.2 и Node.js 24 с npm. Из корня проекта:

```powershell
.\build.ps1
Copy-Item go-config.example.yaml config.go.yaml
.\dist\lanbridge.exe -config config.go.yaml
```

Если `config.go.yaml` уже настроен, не заменяйте его примером. Готовый бинарник
не требует Python, Node.js или Go. Запуск без файла конфигурации использует
параметры по умолчанию:

```powershell
.\dist\lanbridge.exe
```

Адрес: https://localhost:8766. По умолчанию доступ только с этого компьютера.
Создайте администратора в браузере. Пароль — минимум 12 байт, логин — 3–48 латинских
букв, цифр, `_`, `.` или `-`. Остановка: Ctrl+C.

Для настройки скопируйте `go-config.example.yaml` в `config.go.yaml`.
Относительные пути считаются от каталога конфигурации.

```powershell
.\dist\lanbridge.exe -config config.go.yaml
```

Для LAN укажите `server.host: 0.0.0.0` после создания администратора и разрешите
порт только в нужном профиле Windows Firewall. TLS-сертификат генерируется локально;
предупреждение о доверии ожидаемо. Собственные PEM-файлы задаются через `server.cert`
и `server.key`. Старый Python `config.yaml` имеет другую схему и не подходит.

## Параметры

| YAML | По умолчанию | Назначение |
|---|---|---|
| server.host | 127.0.0.1 | Интерфейс сервера |
| server.port | 8766 | HTTPS-порт; не конфликтует с Python 8765 |
| server.cert / server.key | пусто | Собственные PEM; при пустых значениях создаётся пара в runtime/tls |
| storage.data | runtime | БД, TLS, резервные копии, журналы |
| storage.root | runtime/files | Корень файлового хранилища |
| security.session_hours | 168 | Срок сессии, 1–720 часов |
| security.login_attempts | 8 | Лимит неудачных входов с одного IP за 15 минут |
| logs.level | info | debug / info / warn / error |
| logs.max_mb | 5 | Размер текущего журнала |
| logs.backups | 3 | Количество ротированных журналов |
| database.backups | 3 | Число согласованных резервных копий SQLite |
| database.backup_hours | 24 | Период резервирования; копия также создаётся при запуске |
| database.max_mb | 512 | Максимальный размер основной SQLite, 16–16384 МиБ; WAL и копии считаются отдельно |
| external.cloudflared | cloudflared | Имя в PATH или путь к бинарнику; туннель включается только явно |

Переменные процесса переопределяют YAML: `LANBRIDGE_GO_CONFIG`, `LANBRIDGE_GO_HOST`,
`LANBRIDGE_GO_PORT`, `LANBRIDGE_GO_DATA`, `LANBRIDGE_GO_ROOT`, `LANBRIDGE_GO_CERT`,
`LANBRIDGE_GO_KEY`, `LANBRIDGE_GO_LOG_LEVEL`, `LANBRIDGE_GO_CLOUDFLARED`.
Файл `.env.go` рядом с конфигурацией загружается без замены уже заданных переменных процесса.
Префикс GO изолирует новую версию от переменных работающего Python-сервера.

## Реализовано

- Один Go-процесс, встроенные статические файлы, TLS, healthz, завершение по сигналу.
- SQLite WAL/NORMAL, миграция в транзакции, quick_check при запуске, согласованные
  резервные копии с ротацией; session/audit cleanup и checkpoint.
- Первый администратор, Argon2id, роли admin/user, ограничение входа, хеши сессий,
  CSRF, Origin, безопасные cookie и заголовки, аудит.
- JSON API настроек оформления, список/создание пользователей для администратора.
- SSE с ограниченными очередями; начальный снимок и изменения настроек.
- Preact-интерфейс, локальный Inter, две темы и системная тема, левое меню и нижняя
  мобильная навигация. Формы входа/setup, настройки, добавление пользователей и 404.
- Выбор акцента, плотности, размера шрифта, названия, подписи и часового пояса;
  сохранение в SQLite и обновление других вкладок через SSE. Переподключение с
  увеличивающейся задержкой; offline не сбрасывает содержимое страницы.

## Сборка и проверки разработчика

Нужны Go 1.27.2 и Node.js 24 с npm. Зависимости зафиксированы в go.sum и package-lock.
Для готового бинарника эти инструменты не нужны. PowerShell-скрипт ищет Go в PATH,
в LANBRIDGE_GO_TOOLCHAIN или в локальном кеше переносного SDK.

```powershell
.\build.ps1
go test ./...
go vet ./...
.venv\Scripts\python.exe -m playwright install chromium
.venv\Scripts\python.exe scripts/verify_go_ui.py
.venv\Scripts\python.exe scripts/verify_go.py --seconds 20
```

Если Go не добавлен в PATH, для тестов используйте полный путь к SDK, указанный
в LANBRIDGE_GO_TOOLCHAIN. Python-скрипты проверок используют dev-зависимости прежней
версии: Playwright, psutil и Pillow; это инструменты разработчика, не runtime.
В Linux предусмотрен `make build`; его выполнение на Linux пока не подтверждено.
Кросс-сборка Windows → Linux: `build.ps1 -Target linux -Arch amd64`.
Обработчик Windows-службы и файлы systemd/Docker подготовлены; состояние
реальных проверок и инструкции: [go-deployment.md](go-deployment.md).

## Мониторинг

Работают TCP, HTTP(S) (код, ключевое слово в первых 512 КиБ, срок TLS), ICMP через
системный ping, DNS (A/AAAA/CNAME/MX/TXT/NS, системный или заданный резолвер) и
входящий heartbeat. Интервал от 5 с, таймаут до 60 с и не больше интервала, до 20
ошибок до сбоя. Одновременно выполняется не более 16 проверок, очередь результатов
ограничена 256 элементами; запись пачками по 128 элементов или каждые 500 мс.

В «Обзоре сети» можно создать, изменить, клонировать, поставить на паузу и удалить
проверки. Массовые действия доступны через чекбоксы. Список рисует только видимые
строки. Группа WAN используется для карточки интернета; без такой проверки данных
интернета нет. График показывает среднюю задержку выбранного периода по всем проверкам.

После заданного числа ошибок создаётся инцидент, при первом успешном результате он
закрывается. Начало, окончание и причина доступны в журнале. Uptime пока считается
как доля успешных **измерений** по агрегатам, не как точная доля секунд доступности.
Сырые точки сохраняются 48 ч, затем остаются часовые агрегаты; после 30 дней — суточные.
Агрегаты удаляются через год. Heartbeat URL показывается один раз при создании проверки;
его нужно сохранить как секрет и вызывать POST чаще интервала проверки.

Дополнительные API: GET/POST `/api/monitors`, PUT `/api/monitors/{id}`, POST
`/api/monitors/bulk`, GET `/api/monitors/history?window=1h|24h|7d|30d`, GET
`/api/incidents`, POST `/api/heartbeat/{token}`. Изменения проверок доступны только
администратору. Heartbeat использует собственный секретный токен, без сессионного CSRF.

## Пароли и роли

В «Настройки → Учётные записи» каждый пользователь может сменить свой пароль.
Администратор дополнительно может изменить роль или установить новый пароль
другому пользователю. Требуется текущий пароль инициатора; новый — 12–256 байт.
Нельзя понизить последнего администратора. Переименование и удаление учётных
записей пока не реализованы.

API: `PATCH /api/users/{id}` с полями `current_password` и `password` и/или `role`.
Нужны сессия и CSRF. Обычный пользователь может менять только свой пароль.
Изменения, отзыв всех сессий/гостевых ссылок пользователя и запись аудита проходят
в одной транзакции. Пароли в аудит не попадают. После изменения собственной
учётной записи нужен повторный вход. Начатые передачи не прерываются.

## Проверка чистого клона Windows

Нужны Git, Go 1.27.2, Node.js 24, PowerShell и Python 3.10+; Python используется
только для проверки. В скрипте нет сторонних Python-зависимостей.

```powershell
python scripts/verify_go_clean_clone.py
```

Скрипт клонирует текущий коммит локального репозитория без локальных Git-ссылок
в новую `.verification/clean-clone-*/source`, выполняет `build.ps1`, Go-тесты и vet,
копирует пример конфигурации и запускает собранный бинарник. Проверяются встроенные
JS/CSS, первый администратор, файловая папка, ресурсы, сохранение сессии и папки
после остановки/повторного запуска. В конце `git status` клона должен быть пустым.
Порт выбирается свободный через документированную переменную `LANBRIDGE_GO_PORT`,
чтобы не останавливать рабочий сервер. TLS в тестовом HTTPS-клиенте не проверяется,
поскольку сертификат локальный; это не проверка доверия браузера на другом устройстве.

Клон и отчёты `build.log`, `server.log`, `result.json` сохраняются в `.verification`.
В клоне остаются только одноразовые тестовые данные. Проверка использует установленные
SDK и кеши пакетов текущего компьютера: она не заменяет прогон на чистой Windows,
Linux, телефоне или в Docker. Проверенный исходный коммит записывается в result.json.

Просмотр событий администратора и границы аудита: [журнал аудита](go-audit.md).

## Стартовая страница

Администратор выбирает её в «Настройки → Ваша сеть → Стартовая страница»:
обзор, устройства, инциденты или файлы. Настройка общая для пользователей сервера
и сохраняется в `appearance.home_page`. После входа или открытия адреса без
фрагмента выбирается эта страница; явный `/#files`, `/#overview` и другие маршруты
имеют приоритет. Неизвестный явный маршрут по-прежнему показывает 404.
Старые настройки без этого поля используют обзор. Изменение применяется через
обычное сохранение настроек и событие обновления; отдельный перезапуск не требуется.

Проверены старый JSON настроек, допустимые/недопустимые значения API, выбор в
браузере, повторное открытие адреса и приоритет явного маршрута.

## Формат даты и часовой пояс

В «Настройки → Ваша сеть» администратор выбирает часовой пояс и формат даты:
`ДД.ММ.ГГГГ` (по умолчанию) либо `ГГГГ-ММ-ДД`. Настройки общие для пользователей
сервера и обновляются в открытых вкладках. Они применяются к мониторам,
инцидентам, устройствам, файлам/корзине, передачам, аудиту, доставке уведомлений,
гостевым ссылкам в личном интерфейсе и журналу внешнего доступа.
Гостевая страница без входа показывает время в часовом поясе браузера.
Наведите указатель на дату, чтобы увидеть используемый часовой пояс.

API `/api/settings`: `timezone` по умолчанию `Europe/Moscow`, `date_format`
принимает `dmy` или `iso`. Старые настройки без поля формата используют `dmy`.
Числовые timestamps API/БД и длительности передач не изменяются.
При отсутствии часового пояса в базе браузера отображение использует UTC.
Unit-тесты проверяют смену календарного дня, летнее время и ошибочные даты;
браузерный тест — обновление формата/пояса открытого аудита после сохранения.

## Группы проверок в обзоре

Список проверок можно ограничить группой через «Группа проверок» или нажатием
названия в «Состояние инфраструктуры». Повторное нажатие снимает фильтр.
Поиск продолжает работать внутри выбранной группы. WAN, LAN и произвольные
группы отображаются без учёта регистра; группы с собственными названиями больше
не теряются из сводки.

Администратор задаёт порядок в «Настройки → Порядок групп проверок»: одно
название на строку, максимум 32. Пустые строки формы пропускаются. Группы вне
списка идут после перечисленных по алфавиту. Порядок применяется и к списку
проверок; внутри группы сохраняется серверная сортировка. Изменение порядка
не переименовывает группы самих проверок. API `/api/settings` хранит
`group_order`, по умолчанию `["WAN","LAN","DNS","Хранилище","Heartbeat"]`.
Пустой массив означает алфавитный порядок всех существующих групп.

Состояние группы учитывает все активные проверки: хотя бы один сбой — «Сбой»,
все успешны — «Работает», иначе «Ожидание». Полностью приостановленная группа
показывает «Пауза». Карточка интернета использует группу WAN: её состояние и
средний отклик только успешных активных проверок. Это не скорость доступа в интернет.

Проверка чистого клона дополнительно сравнивает байты встроенных PDF-чанков и
лицензий с артефактами сборки, чтобы отложенный просмотрщик был доступен и после
переноса исполняемого файла. Текущие замеры: [performance.md](performance.md#pdf-размеры-папок-и-обновление-дерева--16-октября-2026).

## Группы графика задержки

В обзоре у графика есть отдельный выбор группы (WAN, LAN или другая настроенная
группа). «Все группы» сохраняет общий график. Выбор не меняет фильтр списка проверок
и общую карточку доступности за 30 дней. Периоды: 1 час, 24 часа, 7 и 30 дней.
Обновление каждые 20 секунд при видимой вкладке; при возвращении вкладки данные
запрашиваются сразу. При ошибке видны предупреждение и последние данные.

API: `GET /api/monitors/history?window=24h&group=WAN`. Требуется вход.
`group` — точное название группы с учётом регистра; без него выбираются все группы.
Группы из разных регистров здесь доступны отдельно. Можно сочетать с `id` проверки.
Несуществующая группа возвращает пустой массив, а не общую историю. Отбор идёт по
текущей группе проверки: после переноса проверки её прошлые измерения также видны
в новой группе. Задержка — среднее по выполненным попыткам (включая неуспешные),
доступность — доля успешных попыток; это не процент времени без сбоев.

## Порядок карточек обзора

В настройках → «Ваша сеть» администратор меняет порядок четырёх карточек
кнопками ↑/↓ и нажимает «Сохранить настройки». Порядок общий для всех пользователей,
применяется на десктопе и телефоне, обновляется через SSE в открытых вкладках.
Он сохраняется после перезапуска. Блок ресурсов сервера расположен отдельно.

Поле `card_order` в `/api/settings` — перестановка всех четырёх значений:
`availability`, `internet`, `checks`, `devices`. Повторение, пропуск или неизвестный
идентификатор возвращают 400 без сохранения. Старые настройки без этого поля
используют перечисленный порядок по умолчанию.
