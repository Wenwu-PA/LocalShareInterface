# Go-версия: каркас и интерфейс

Разрабатывается рядом с Python-версией. Исполняемый файл: `dist/lanbridge.exe`.
Python-версия продолжает запускаться через `python run.py` и использует свою БД.

## Запуск Windows

Из корня проекта после сборки:

```powershell
.\dist\lanbridge.exe
```

Адрес: https://localhost:8766. По умолчанию доступ только с этого компьютера.
Создайте администратора в браузере. Пароль — минимум 12 байт, логин — 3–48 латинских
букв, цифр, `_`, `.` или `-`. Остановка: Ctrl+C.

Для настройки скопируйте `go-config.example.yaml` в `config.go.yaml`.
Относительные пути считаются от каталога конфигурации.

```powershell
.\dist\lanbridge.exe -config config.go.yaml
```

Для LAN укажите `server.host: 0.0.0.0` после создания администратора и разрешите
порт только в нужном профиле Windows Firewall. TLS-сертификат генерируется локально;
предупреждение о доверии ожидаемо. Собственные PEM-файлы задаются через `server.cert`
и `server.key`. Старый Python `config.yaml` имеет другую схему и не подходит.

## Параметры

| YAML | По умолчанию | Назначение |
|---|---|---|
| server.host | 127.0.0.1 | Интерфейс сервера |
| server.port | 8766 | HTTPS-порт; не конфликтует с Python 8765 |
| server.cert / server.key | пусто | Собственные PEM; при пустых значениях создаётся пара в runtime/tls |
| storage.data | runtime | БД, TLS, резервные копии, журналы |
| storage.root | runtime/files | Будущее файловое хранилище; файловый API ещё не подключён |
| security.session_hours | 168 | Срок сессии, 1–720 часов |
| security.login_attempts | 8 | Лимит неудачных входов с одного IP за 15 минут |
| logs.level | info | debug / info / warn / error |
| logs.max_mb | 5 | Размер текущего журнала |
| logs.backups | 3 | Количество ротированных журналов |
| database.backups | 3 | Число согласованных резервных копий SQLite |
| database.backup_hours | 24 | Период резервирования; копия также создаётся при запуске |

Переменные процесса переопределяют YAML: `LANBRIDGE_GO_CONFIG`, `LANBRIDGE_GO_HOST`,
`LANBRIDGE_GO_PORT`, `LANBRIDGE_GO_DATA`, `LANBRIDGE_GO_ROOT`, `LANBRIDGE_GO_CERT`,
`LANBRIDGE_GO_KEY`, `LANBRIDGE_GO_LOG_LEVEL`. `.env` пока не загружается автоматически.
Префикс GO изолирует новую версию от переменных работающего Python-сервера.

## Реализовано

- Один Go-процесс, встроенные статические файлы, TLS, healthz, завершение по сигналу.
- SQLite WAL/NORMAL, миграция в транзакции, quick_check при запуске, согласованные
  резервные копии с ротацией; session/audit cleanup и checkpoint.
- Первый администратор, Argon2id, роли admin/user, ограничение входа, хеши сессий,
  CSRF, Origin, безопасные cookie и заголовки, аудит.
- JSON API настроек оформления, список/создание пользователей для администратора.
- SSE с ограниченными очередями; начальный снимок и изменения настроек.
- Preact-интерфейс, локальный Inter, две темы и системная тема, левое меню и нижняя
  мобильная навигация. Формы входа/setup, настройки, добавление пользователей и 404.
- Выбор акцента, плотности, размера шрифта, названия, подписи и часового пояса;
  сохранение в SQLite и обновление других вкладок через SSE. Переподключение с
  увеличивающейся задержкой; offline не сбрасывает содержимое страницы.

## Сборка и проверки разработчика

Нужны Go 1.27.2 и Node.js 24 с npm. Зависимости зафиксированы в go.sum и package-lock.
Для готового бинарника эти инструменты не нужны. PowerShell-скрипт ищет Go в PATH,
в LANBRIDGE_GO_TOOLCHAIN или в локальном кеше переносного SDK.

```powershell
.\build.ps1
go test ./...
go vet ./...
.venv\Scripts\python.exe -m playwright install chromium
.venv\Scripts\python.exe scripts/verify_go_ui.py
.venv\Scripts\python.exe scripts/verify_go.py --seconds 20
```

Если Go не добавлен в PATH, для тестов используйте полный путь к SDK, указанный
в LANBRIDGE_GO_TOOLCHAIN. Python-скрипты проверок используют dev-зависимости прежней
версии: Playwright, psutil и Pillow; это инструменты разработчика, не runtime.
В Linux предусмотрен `make build`; его выполнение на Linux пока не подтверждено.
Кросс-сборка Windows → Linux: `build.ps1 -Target linux -Arch amd64`.
Службы Windows/systemd и Docker новой версии ещё не подготовлены.

## Мониторинг

Работают TCP, HTTP(S) (код, ключевое слово в первых 512 КиБ, срок TLS), ICMP через
системный ping, DNS (A/AAAA/CNAME/MX/TXT/NS, системный или заданный резолвер) и
входящий heartbeat. Интервал от 5 с, таймаут до 60 с и не больше интервала, до 20
ошибок до сбоя. Одновременно выполняется не более 16 проверок, очередь результатов
ограничена 256 элементами; запись пачками по 128 элементов или каждые 500 мс.

В «Обзоре сети» можно создать, изменить, клонировать, поставить на паузу и удалить
проверки. Массовые действия доступны через чекбоксы. Список рисует только видимые
строки. Группа WAN используется для карточки интернета; без такой проверки данных
интернета нет. График показывает среднюю задержку выбранного периода по всем проверкам.

После заданного числа ошибок создаётся инцидент, при первом успешном результате он
закрывается. Начало, окончание и причина доступны в журнале. Uptime пока считается
как доля успешных **измерений** по агрегатам, не как точная доля секунд доступности.
Сырые точки сохраняются 48 ч, затем остаются часовые агрегаты; после 30 дней — суточные.
Агрегаты удаляются через год. Heartbeat URL показывается один раз при создании проверки;
его нужно сохранить как секрет и вызывать POST чаще интервала проверки.

Дополнительные API: GET/POST `/api/monitors`, PUT `/api/monitors/{id}`, POST
`/api/monitors/bulk`, GET `/api/monitors/history?window=1h|24h|7d|30d`, GET
`/api/incidents`, POST `/api/heartbeat/{token}`. Изменения проверок доступны только
администратору. Heartbeat использует собственный секретный токен, без сессионного CSRF.

## Уведомления и инциденты

Telegram/SMTP/Webhook, очередь SQLite, повторы после перезапуска и внешний heartbeat
подключены к новой странице уведомлений. В инцидентах доступны история, заметки
и CSV. Настройка и границы проверки: [go-notifications.md](go-notifications.md).

## Ещё не реализовано

Cloudflare Quick Tunnel реализован и проверен локальной имитацией провайдера:
[go-external.md](go-external.md). Реальная публикация, NetBird и SSH не проверены.
Нет установки как службы. Linux amd64 скомпилирован с Windows, но запуск на Linux не проверен.
Повреждённая БД обнаруживается и запуск останавливается; автоматическое восстановление
из копии пока не реализовано. Лимит размера БД также впереди. Файловые квоты и хранилище описаны в
[go-files.md](go-files.md).

50 и 100 HTTP-мониторов проверены короткими прогонами; замеры в
[отчёте](performance.md). Передача 20 ГиБ с перезапуском и проверкой SHA-256 пройдена: [go-files.md](go-files.md).
24-часовой прогон и 60 fps ещё не измерены.
Перетаскивание порядка групп ещё не подключено. Карточки CPU/RAM/диска тоже впереди.
Тег v0.1.0 не устанавливается.

## API каркаса

| Метод и путь | Доступ |
|---|---|
| GET /healthz | Публично: состояние БД, версия, uptime процесса |
| GET /api/status | Публично: требуется ли setup, текущая сессия, CSRF |
| POST /api/setup | Только при пустой базе + CSRF |
| POST /api/login | CSRF + лимит по IP |
| POST /api/logout | Сессия + CSRF |
| GET /api/me | Сессия |
| GET /api/settings | Сессия |
| PUT /api/settings | Администратор + CSRF |
| GET /api/events | Сессия, SSE |
| GET /api/users | Администратор |
| POST /api/users | Администратор + CSRF |

При изменениях отправляйте `Content-Type: application/json`, cookie и
`X-CSRF-Token` из ответа status/login. После входа CSRF обновляется.
Ошибки JSON содержат `code` и `error`. Гостевой доступ: [go-shares.md](go-shares.md).
