Working Set — резидентная физическая память. Private Bytes включает выделенную
процессу память, не обязательно находящуюся в RAM. По этой второй метрике 60 МБ
пока не достигнуты. Ограничение Go heap 40 МиБ не гарантирует лимит всей памяти ОС.
Параллельные вычисления Argon2 ограничены одним запросом.

Эти результаты относятся только к каркасу. Приёмка бюджета при 50 мониторах не
проведена, так как планировщик ещё не реализован. Прогон 100 мониторов / 20 с,
24 часа, 20+ ГиБ и 60 fps ещё не выполнен. Нельзя считать их пройденными по данным
короткого запуска.

## Обрывы HTTPS-передач 18 октября 2026

```powershell
.venv\Scripts\python.exe scripts/verify_go_disconnects.py
```

Сценарий запускает собранный `dist/lanbridge.exe` на случайном loopback-порту
с временной БД и папкой. Пользовательские настройки и файлы не используются.
После первого принятого чанка три HTTPS-запроса объявляют 1 МиБ, отправляют
только 64 КиБ посторонних байтов и закрывают соединение. Повторная загрузка
продолжается с последней подтверждённой позиции; публикация файла 16 МиБ проходит
серверную проверку SHA-256.

Скачивание прерывается после 64 КиБ, затем продолжается новым запросом Range.
Проверяются ответ 206, Content-Range, полный SHA-256 и две записи истории:
`interrupted` для оборванного скачивания и `partial` для завершённого Range.
Сервер остаётся доступным; panic и ошибки уровня ERROR отсутствуют.

Результат: PASS, файл 16 777 216 байт, SHA-256
`341aacac661ccb210720bedaa9ead5d668fe5ea41a73532fc147c71e34040df1`.
Код приложения: `6fe5edd3aa26d7563cb731e9168dd5981315adb6`.
Отчёт сохраняется в `.verification/go-disconnects.json`.
Это проверка локального обрыва потока, а не физической потери LAN/WAN,
длительного сетевого зависания или заполнения диска.

### Отказы при записи чанка

`TestUploadRecoversFromChunkFailures` проверяет четыре сценария на временной БД:
ошибку чтения после части данных, отмену контекста во время чтения, отказ SQL
при сохранении позиции и отказ из-за завышенного обязательного резерва диска.
Во всех случаях позиция остаётся прежней, подтверждённый префикс сохранён,
а повторный чанк позволяет завершить файл с правильным SHA-256 и содержимым.
После отказа SQL на диске допустим неподтверждённый хвост; следующая попытка
обрезает его по позиции из БД. Все четыре сценария, общий набор Go-тестов,
`go vet` и повторная HTTPS-проверка обрывов прошли 18 октября 2026.
Проверка резерва диска не имитирует системную ошибку ENOSPC во время записи:
физическое заполнение диска остаётся непроверенным.

## Параллельные крупные файлы 18 октября 2026

```powershell
.venv\Scripts\python.exe scripts/verify_go_large_file.py --gib 5 --parallel 3
```

Параметр `--parallel` принимает 1–8, `--gib` — размер каждого файла (1–100 ГиБ).
Для 1 файла сохраняется прежний сценарий остановки процесса и докачки;
при 2–8 запускаются отдельные HTTPS-соединения с барьерами перед загрузкой
и скачиванием. Тест проверяет пересечение времени передач, а не просто запускает
несколько задач. Данные файлов различаются; проверяется SHA-256 каждого файла.
Временные данные удаляются, рабочее хранилище не используется; требуется свободное
место на все файлы плюс 2 ГиБ. Буфер клиента — 1 МиБ на поток.
