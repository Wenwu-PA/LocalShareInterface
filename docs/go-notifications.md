# Уведомления Go-версии

Настройки доступны администратору на странице «Уведомления» по адресу
`https://localhost:8766/#notifications`. Старый Python-сервер использует отдельные настройки.

## Каналы и секреты

Создайте `.env.go` рядом с выбранным файлом конфигурации по образцу
[.env.go.example](../.env.go.example). Этот файл исключён из Git. Формат:
`LANBRIDGE_NAME=value`, один параметр на строку; допустимы одинарные или двойные
кавычки вокруг значения. Подстановки других переменных и многострочные значения
не поддерживаются. Переменные процесса имеют приоритет. После изменения файла
перезапустите Go-сервер.

В интерфейсе задаются **имена** переменных, значения не возвращаются API:

| Канал | Переменные |
|---|---|
| Telegram | `LANBRIDGE_TELEGRAM_TOKEN`, `LANBRIDGE_TELEGRAM_CHAT` |
| Webhook | `LANBRIDGE_WEBHOOK_URL` |
| SMTP | `LANBRIDGE_SMTP_URL`, `LANBRIDGE_SMTP_FROM`, `LANBRIDGE_SMTP_TO` |
| SMTP с авторизацией | Дополнительно `LANBRIDGE_SMTP_USER`, `LANBRIDGE_SMTP_PASSWORD` |
| Внешний наблюдатель | `LANBRIDGE_OBSERVER_URL` |

Добавьте канал, укажите переменные, включите нужные события и сам канал, сохраните.
«Отправить тест» ставит настоящее сообщение в очередь. Результат отображается
в журнале доставки. Одновременно допускается одно ожидающее тестовое сообщение
на канал. Всего можно настроить 16 каналов.

Webhook получает JSON `id`, `monitor_id`, `kind`, `name`, `message`, `at` через POST.
Успехом считается ответ 2xx. Telegram требует также JSON-подтверждения `ok: true`.
Webhook и наблюдатель требуют HTTPS, кроме loopback-адресов для локальной проверки.
Редиректы не выполняются. SMTP URL: `smtp://host:587` с обязательным STARTTLS
либо `smtps://host:465`. Проверка сертификата включена. Один SMTP-канал отправляет
на один адрес; для нескольких получателей создайте отдельные каналы.

## События, очередь и восстановление

Сбой создаётся после заданного в проверке числа ошибок подряд. Восстановление —
после успешной проверки. Запись инцидента и постановка сообщений выполняются в одной
транзакции SQLite. Одинаковые переходы одного монитора на одном канале подавляются
на 5–86400 секунд; сбой и восстановление учитываются отдельно.

Рабочий процесс отправляет сообщения последовательно, с таймаутом до 10 секунд.
После ошибки задержка растёт: 5, 10, 20 секунд и далее до часа. Число попыток
не ограничено. Выключенный канал сохраняет очередь до повторного включения.
После перезапуска сервера очередь продолжает обрабатываться.

Доставка имеет семантику **как минимум один раз**: если получатель принял сообщение,
а сервер остановился до записи подтверждения, возможен повтор. Webhook получает
стабильный `Idempotency-Key`; получатель может использовать его для удаления дублей.
Доставленные записи хранятся 30 дней и очищаются при обработке очереди.
Ожидающие сообщения не удаляются по возрасту. Лимита размера БД пока нет: длительная
недоступность каналов требует контроля свободного места.

## Внешний наблюдатель и резервный канал

Сервер отправляет GET по настроенному URL примерно раз в 30 секунд. Настройте
на стороне независимого наблюдателя тревогу после **90 секунд без сигнала**, а также
получателя тревоги. Локальный сервер показывает время последнего успешного ответа;
это не доказывает, что внешний сервис действительно настроен отправлять тревоги.

При потере WAN уведомление через тот же WAN отправить невозможно. Очередь сохраняет
его до восстановления. Для независимого резервного канала добавьте второй канал
и при необходимости задайте исходящий IP другого интерфейса сервера. Маршрут через
отдельный шлюз/модем должен быть настроен в ОС. Привязка IP сама по себе не создаёт
резервное подключение и не гарантирует независимость DNS.

## Инциденты

На странице «Инциденты» доступны фильтр активных/восстановленных записей, подробная
история по нажатию на имя, заметки администратора и экспорт CSV. Интерфейс получает
500 последних инцидентов, историю до 1000 событий на инцидент; CSV — до 10 000 записей.
CSV экспортируется целиком независимо от фильтра интерфейса. Формулы в текстовых
ячейках нейтрализуются префиксом `'`.

## API

Все изменения требуют сессии администратора и CSRF-токена.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/notifications` | Каналы, последние 100 доставок, наблюдатель |
| POST | `/api/notifications/channels` | Создать канал или обновить по `id` |
| POST | `/api/notifications/test` | Поставить тест в очередь: `{"id":1}` |
| POST | `/api/notifications/heartbeat` | `enabled` и `url_env` наблюдателя |
| GET | `/api/incidents/{id}/events` | События; доступно обычному пользователю |
| POST | `/api/incidents/{id}/notes` | Добавить `message`, до 2000 байт |
| GET | `/api/incidents/export` | CSV; только администратор |

## Проверено и ограничения

Локально проверены Webhook 503 → очередь → принудительная остановка → повторный
запуск → 204, сохранение настроек через браузер, heartbeat, роли, подавление повторов,
очередь более 10 000 записей и отказ SMTP без STARTTLS. Внешние Telegram/SMTP-аккаунты
не подключались: доставка реальным провайдерам и резервный физический канал
не проверены. Наблюдатель проверен локальным HTTP-приёмником, не внешним сервисом.

Проверка из корня репозитория после сборки (нужны dev-зависимости Python и Chromium):

```powershell
.venv\Scripts\python.exe scripts/verify_go_notifications.py
```

Уведомления о новом устройстве подключены к модулю [обнаружения](go-devices.md).
Тихие часы, постоянные напоминания и уведомления о заполнении диска пока не подключены.
