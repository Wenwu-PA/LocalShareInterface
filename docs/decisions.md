# Решения по переходу на Go

Дата: 9 октября 2026. Исходная история: `b9521b5`; разработка в `dev`.

## Область работы и сохранение данных

В репозитории уже есть работающая Python-версия. Она сохраняется вместе с `run.py`,
данными и документацией. Дизайн-пакет добавлен в `design/` без изменения оригиналов.
Новый сервер использует отдельную БД и каталог `runtime/`, чтобы новые миграции не
изменили Python SQLite. Автоматический перенос старых пользователей и данных не
выполняется. Совместное использование одной SQLite-базы двумя реализациями запрещено.

## Стек и бюджет

- Go, `net/http`, `go:embed`, `log/slog`; CGO выключен.
- SQLite через modernc.org/sqlite, WAL, NORMAL, foreign_keys, busy_timeout.
- Preact + Vite, локальный Inter, CSS tokens из `design/build.py`; без CDN.
- SSE: снимок при подключении, затем изменения с монотонным номером; при пропуске
  истории — новый снимок. Ограниченный буфер подписчика, медленный клиент отключается.
- Для runtime нужен только бинарник. Go/Node нужны исключительно для сборки.

Цели: бинарник ≤25 000 000 байт, frontend без шрифтов ≤150 000 байт gzip, RAM
≤60 000 000 байт и CPU <1% при 50 мониторах / 20 с. Это критерии приёмки, не результаты.
Замер Windows включает Working Set и Private Bytes отдельно; CPU — процессорное
время процесса / реальное время, без деления на число ядер. Argon2 выполняется с
ограничением параллелизма; пиковая память входа измеряется отдельно от простоя.
Файловые буферы ≤1 МиБ на соединение, никакого ReadAll для содержимого файлов.
24-часовой прогон и передача 5+ ГиБ обязательны до релиза, короткий smoke их не заменяет.

## Схема БД по этапам

1. `schema_migrations`, `users`, `sessions`, `login_attempts`, `audit`, `settings`.
2. `monitor_groups`, `monitors`, `samples`, `aggregates`, `monitor_state`.
3. `incidents`, `incident_events`, `notification_channels`, `notification_rules`,
   `notification_queue`, `heartbeat_state`.
4. `devices`, `device_observations`, `file_index`, `folder_acl`, `uploads`,
   `upload_chunks`, `trash`, `shares`, `transfers`, `external_connections`.

UTC timestamps в хранилище, локальный часовой пояс только при отображении. Миграция
в транзакции; неизвестная новая версия БД вызывает понятную ошибку, без downgrade.
Один писатель мониторинга с ограниченной очередью, batch каждые 500 мс или 128 записей.
Потеря очереди не маскируется: метрика dropped_samples и предупреждение healthz.
SQLite backup через согласованный снимок; повреждённый оригинал сохраняется перед
восстановлением. Файлы пользователей не являются частью резервной копии БД.

## API и безопасность

`/healthz`; `/api/status`; `/api/setup`; `/api/login`; `/api/logout`; `/api/me`;
`/api/settings`; `/api/events`; далее `/api/monitors`, `/api/incidents`, `/api/devices`,
`/api/diagnostics`, `/api/files`, `/api/uploads`, `/api/shares`, `/api/notifications`,
`/api/external`. JSON ошибки: `{error, code}`, без stack trace.
Setup/login защищены CSRF так же, как остальные изменения. Cookie Secure, HttpOnly,
SameSite Strict; сессия случайная, в БД только хеш. Валидация Origin, запрет CORS,
ограничение body, rate limit входа, CSP только self. Пароли Argon2id.
Первый запуск привязан к loopback; LAN-доступ включается явно конфигурацией.

## Последовательность и контрольная точка дизайна

1. Каркас Go, миграции, HTTPS, auth, встроенный frontend, shutdown, healthz; тесты.
2. Дизайн-система, тёмная/светлая темы, desktop/mobile; показать отсутствующие экраны
   Устройства, Настройки, Вход, Первый запуск и Ошибка **до остальных этапов**, как
   запрошено в задании. Проектируемые функции не выдаются за работающие.
3. Мониторы и агрегаты → инциденты/уведомления → устройства/диагностика.
4. Файлы/папки/ACL/квоты → ссылки/QR → внешний доступ → кастомизация.
5. Нагрузочный прогон, службы, кросс-сборка, чистая установка, финальный отчёт.

После каждого этапа: запуск, критические тесты, измерения применимых бюджетов,
обновление README, Conventional Commit. `main` не меняется до проверенной интеграции.
Внешние тестовые сообщения и реальное включение публичного туннеля требуют настроенных
пользователем адресатов/учётных данных; случайным адресатам сообщения не отправляются.
